### Подготовь серверную часть AmneziaWG и отдельные подключения устройств

Основной путь — серверная часть amneziawg-go и amneziawg-tools на моём VPS,
отдельное приложение AmneziaWG на компьютере и телефоне с импортом готового `.conf`
или QR-кода настроек, если приложение его поддерживает. На устройствах AmneziaVPN
для этого пути не требуется. У AmneziaWG нет мастера установки сервера.
Не подменяй этот путь установкой через AmneziaVPN из Hosting Architect.

Перед выполнением открой актуальные первоисточники и прочитай инструкции выбранной версии.

- [Приложение и импорт](https://docs.amnezia.org/documentation/instructions/use-amneziawg-app/).
  Для моего VPS используй Self-hosted, раздел Premium относится к другой услуге.
- [Серверная часть](https://docs.amnezia.org/documentation/instructions/install-amneziawg-go/).
- [Официальные исходники amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go).
- [Официальные инструменты amneziawg-tools](https://github.com/amnezia-vpn/amneziawg-tools).
- [Поддерживаемые системы](https://docs.amnezia.org/documentation/supported-linux-os-for-vps/).
  Учитывай, что требования этой страницы описывают установку через AmneziaVPN,
  совместимость прямой сборки проверяй также по выбранным исходникам.

Все серверные команды выполняй **на VPS**. Если ты запущен на моём компьютере,
используй SSH к VPS, не устанавливай серверные службы локально.
В рамках этого поручения разрешаю необходимые настройки создаваемого собственного VPN
на моём новом личном VPS. Сохраняй существующие чужие VPN, службы, маршруты и SSH-доступ.
Обычные разрешённые шаги выполняй без повторного согласования. Спрашивай только реально
недостающие данные и действия, которые должен выполнить я. Не переноси чужие адреса,
имена, ключи или настройки из примеров и прежних установок.

1. Уточни системы и версии приложений на моих устройствах. Выбери проверяемую совместимую
   версию серверного кода и tools. Сверь поддерживаемые параметры с клиентом, включая
   ограничения AWG3.1. Не выбирай несовместимые параметры по слову latest.
   Проверь требование Go в go.mod выбранного исходного кода и установи подходящую версию
   из официального источника. Не считай системный пакет Go заведомо достаточным.
2. Получи официальные исходники, проверь инструкции сборки и выполни сборку и установку
   серверной части и инструментов awg/awg-quick на VPS. В проверенном у владельца способе
   использовалась сборка go build. Для выбранной версии сверь реальную команду сборки,
   включая Makefile, с её исходниками. Не придумывай установщики и команды скачивания.
   Не запускай случайные root-скрипты и непроверенную команду «всё одной строкой».
3. Создай новые собственные ключи безопасными штатными средствами, отдельную пару каждому
   устройству. Закрытые ключи храни в закрытых файлах с доступом только владельцу,
   не выводи их в чат, журналы или отчёт. Выбери свободную внутреннюю подсеть без пересечений,
   отдельный peer-адрес — внутренний адрес подключения — каждому устройству.
   Настрой сервер и разрешённые адреса каждого подключения, согласованные параметры
   AmneziaWG и публичные ключи. Не копируй одну конфигурацию нескольким устройствам.
4. Выбери свободный UDP-порт, разреши его в действующих правилах сервера, сохраняя SSH
   и существующие правила. Если панель Hosting требует моего ручного действия, дай его
   через [панель](https://my.amnezia.host/aff.php?aff=158) и дождись подтверждения.
   Для MAX сохрани TCP 443 и TCP 80 для сертификата. Чужие службы не останавливай.
5. Настрой forwarding — передачу пакетов между подключениями, маршрутизацию — путь трафика,
   NAT — выход устройств в интернет через сервер, и DNS — определение адресов сайтов.
   Правила должны касаться создаваемой VPN-подсети и фактического внешнего подключения.
   Согласуй клиентские маршруты для всего обычного интернета. Для IPv6 проверь возможность
   реальной передачи на VPS и устройстве, настрой её при поддержке. Если поддержки нет,
   явно укажи ограничение и исключи обход VPN через IPv6 в этом подключении, сохраняя
   остальные настройки. Не обещай полный IPv6 без проверки реального трафика.
6. Настрой запуск через awg-quick с выбранной серверной реализацией и автозапуск штатной
   службой системы. Проверь фактические пути программ и описание службы выбранной версии.
   Сохрани необходимые правила после перезапуска без перезаписи чужих правил.
   Бинарник и пустой интерфейс — только подготовка, работающий VPN требует передачи трафика.
7. Выдай отдельные доступы готовым инструментом проекта `vpn_access.py`.
   Установи `python3`, `iproute2`, `qrencode` из системных пакетов и выполни на VPS
   `sudo install -m 755 vpn_access.py /usr/local/bin/telemax-vpn` из скачанного проекта.
   Установщик пересылки также устанавливает этот инструмент. Проверь реальные пути `awg`
   и `awg-quick` из официальных tools, доступные при запуске через `sudo`.
   Выполни подготовку, подставив проверенные значения вместо обозначений в угловых скобках.

   ```sh
   sudo telemax-vpn prepare \
     --server-config '<полный путь к настоящему файлу интерфейса.conf>' \
     --endpoint '<публичный IP:фактический UDP-порт>' \
     --dns '<проверенные адреса DNS через запятую>' \
     --routes '0.0.0.0/0, ::/0' \
     --client-format '<1 или 2 после проверки приложения>'
   sudo telemax-vpn add phone
   sudo telemax-vpn add laptop
   ```

   Это шаблон команды подготовки. Замени все обозначения реальными данными и выполни
   фактическую выдачу на моём VPS. Публичный IP сверь с панелью и сетевыми настройками,
   порт должен совпадать с действующим серверным. Перенаправление внешнего порта инструмент
   не поддерживает. DNS должен работать через созданный VPN. Для раздельных маршрутов
   передай согласованный список. При полном подключении сохраняй маршрут `::/0` также
   на сервере только с IPv4, чтобы трафик IPv6 направлялся в это подключение. Отдельно
   проверь, что приложение действительно исключило выход IPv6 мимо VPN.
   Укажи формат `1` для совместимых параметров AWG1. Формат `2` разрешён после подтверждения
   поддержки AWG2 установленной версией отдельного AmneziaWG, включая S3/S4, диапазоны H
   и подписи I1–I5. Выдача отказывается от параметров AWG3.1 и неизвестных полей.
   При несовместимости сохрани сервер и подбери проверенный совместимый путь отдельно.
   Поддерживается одна серверная подсеть каждого вида адресов, прямой публичный IP и
   `SaveConfig=false`. При новой установке зафиксируй это до первого запуска службы.
   Если эти условия отсутствуют у уже работающего сервера, сохрани его и объясни ограничение.
   Инструмент сверяет ключ, порт, обфускацию — маскировку соединения, и адреса в постоянном
   файле и действующем интерфейсе. Из обоих источников резервирует занятые адреса.
   Он создаёт ключи через `awg genkey`, `awg pubkey`, `awg genpsk`, сохраняет клиента
   постоянно и добавляет его через `awg set`, затем проверяет результат. Остальные клиенты
   и общие сетевые правила сохраняются. Повтор по имени возвращает прежний доступ,
   одновременная выдача защищена блокировкой. При ошибке изменения интерфейса выполняется
   откат, при обрыве сохранённая запись восстановления обрабатывается следующим `add`.
   При внешнем изменении настроек требуется ручная проверка закрытой записи восстановления.
   Папки выдачи имеют права `700`, настройки и QR — `600`, по умолчанию в `/etc/telemax-vpn`.
   При слишком большом QR выдача сохраняет рабочий `.conf` и возвращает код `2` с предупреждением.
   Помоги получить `.conf` и `.png` способом из раздела «Выдача доступов командой» руководства
   в моём личном терминале. Просмотр QR делаю я на своём устройстве, содержимое файлов
   сохраняй вне ответов модели, журналов и публичных веб-серверов. При последующем запуске
   помощника используй уже сохранённый профиль и `add`, сохраняй имена устройств.
   Помоги установить отдельное AmneziaWG из официального источника и импортировать настройки.
8. Попроси включить подключение на телефоне через мобильную сеть и открыть сайты и Telegram.
   Сверь успешное установление защищённого соединения и рост счётчиков передачи на сервере
   без вывода ключей. Проверь реальную загрузку обычных сайтов, DNS, выход через свой VPS,
   IPv4 и отдельно IPv6. Затем проверь компьютер с его отдельным подключением.
   Отметь, что реально проверено, включая недоступный IPv6. Состояние «подключено»
   и успешная команда не заменяют обмен с телефона.

Покупку, импорт на устройстве, QR-вход, второй пароль и привязку выполняю я.
Давай одно понятное ручное действие за раз и жди результата. Секреты ввожу скрыто
в личном терминале, модель их не получает. Не запрашивай скриншоты с ключами и QR.

### Установи пересылку по существующей инструкции

Помоги подготовить мой отдельный бот MAX по официальным требованиям из GUIDE_RU.md,
мой домен с прямой записью на адрес сервера и защищённый адрес приёма сообщений.
Проверь фактическое соответствие домена серверу и доступность нужных портов.

Выполни шаг установки из GUIDE_RU.md в окне моего сервера, включая запуск установщика,
а затем настройку и запуск пересылки. Используй только исходники
https://github.com/fdrvaa84/telegram-max-bridge и существующий install.sh после чтения.
На новом VPS после получения и чтения исходников выполни
`sudo bash /usr/local/src/telegram-max-bridge/install.sh` из шага 7 инструкции.
Если код уже получен, проверь его источник и незаконченные изменения, не отменяй их.
Не используй инфраструктуру автора, чужие ключи, ботов, служебные адреса или базы.
Не меняй код программы и зависимости ради установки. Не подключай дополнительные
облака и другие необязательные возможности без отдельной просьбы.

Перед запуском установщика и команд настройки выясни по состоянию установки, какие действия уже завершены. Готовые настройки,
привязку и вход повторять не нужно. Продолжай с первого незавершённого шага.
Для новой установки следуй порядку инструкции — `sudo telemax configure`, `sudo telemax https`,
`sudo telemax pair`, `sudo telemax login`, `sudo telemax start`, `sudo telemax status`.
Команды с личным вводом запускаю я в своём терминале. Для привязки отправляю строку
только своему боту в личном MAX, проверяю свой аккаунт и подтверждаю в окне сервера.
QR-код сканирую средствами Telegram на телефоне. Проверяй результат каждого шага,
не переходи через неуспешную привязку, вход или выпуск сертификата.
Не обходи ограничения Telegram и MAX частыми повторами. Сохраняй очередь, тексты, вход и связи ответов. Учтённые местные вложения программа удаляет автоматически только после подтверждённой доставки сообщения со всеми вложениями. При ошибке или неопределённом результате сохраняй файлы для повторной попытки. Если пользователь включил необязательное облачное копирование, очистка должна дождаться проверки обеих копий. По умолчанию облачное копирование выключено. Сохраняй файлы, нужные другим незавершённым отправкам и облачным задачам. После перезапуска очистка продолжается по сохранённому состоянию, включая ранее доставленные учтённые вложения, без их повторной рассылки.

### Проверь реальную работу

Используй только мою служебную проверочную группу и личный проверочный диалог с согласившимся
участником. Никаких сообщений клиентам и посторонним адресатам. Ручные отправки выполняю
я или согласившийся участник. Для проверки тем нужна своя проверочная группа с темами.

1. VPN включён на телефоне через мобильную сеть, сайты и Telegram доступны, обмен
   подтверждён на сервере. IPv4 и IPv6 отмечены отдельно по фактической проверке.
2. Новое входящее личное сообщение Telegram появляется в моём MAX. «Ответить» под копией
   возвращает ответ от моего аккаунта в исходный диалог под исходное сообщение.
3. В служебной группе проверь обращение через точное @имя, упоминание выбором пользователя
   и ответ на моё сообщение. Проверь также обычную группу, большую группу и группу с темами
   по разделу «Живая проверка». Обычное сообщение без обращения ко мне не должно пересылаться.
4. «Ответить» из MAX под каждой проверяемой копией попадает в исходную группу,
   под исходное сообщение и в исходную тему. Факт доставки проверь на обеих сторонах.
5. Проверь фото с подписью, документ, короткое видео, голосовое и кружочек в обе стороны.
   Объясни преобразования из раздела «Форматы и ограничения». В частности, фото может менять
   качество, голосовое Telegram в MAX становится аудиозаписью, кружочек — обычным видео,
   а видео из MAX становится кружочком только по явному выбору и в пределах ограничений.
   Не обещай исходное качество и поддержку всех форматов. Отдельно проверь отказ чужому
   аккаунту MAX по инструкции, если есть согласившийся проверочный участник.
   Убедись в обоих направлениях, что после подтверждённой доставки всех вложений местные оригиналы и подготовленные файлы удалились, а ответ по сохранённой связи попадает в тот же чат, группу и тему. Проверки отказов и неопределённого результата выполняй безопасными местными подменами отправки без сообщений посторонним. Отдельно проверь сохранение файлов при незавершённой отправке, ожидании облачных копий и нескольких потребителях, а также продолжение очистки после перезапуска. Отличай такие проверки от реальной отправки.
6. Перезапусти только пересылку через `sudo telemax restart`, проверь состояние и новое
   сообщение. Ответ на копию, полученную до перезапуска, должен сохранить исходное назначение.
   Для проверки очереди останови только пересылку через `sudo telemax stop`, попроси отправить
   новое проверочное сообщение и запусти `sudo telemax start`. Убедись, что оно дочиталось
   и доставлено без повторной отправки старых сообщений. Не удаляй очередь и связи.
7. Проверь обмен с телефона при выключенном компьютере. Согласуй удобный момент перезагрузки
   моего нового сервера, предупредив о кратком перерыве VPN. После неё повтори проверку VPN,
   сообщения и ответа на прежнюю копию. Без этого работа после перезагрузки не подтверждена.

Успешный запуск команды и состояние «работает» не заменяют проверку доставки. Если этап
недоступен, запиши «не проверено» и конкретную причину. При неизвестном результате отправки
сначала сверь обе стороны, не повторяй отправку вслепую. При ошибке используй безопасные
`sudo telemax status` и `sudo telemax logs`, скрывая личные сведения, и раздел решения проблем.
Заверши коротким итогом простыми словами — что действительно работает, что осталось
непроверенным, и одно следующее действие для меня.
