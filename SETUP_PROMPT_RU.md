3. Установи AmneziaWG и выдай доступы

Выбранный способ — AmneziaWG-Go и официальные инструменты AmneziaWG на сервере,
отдельное приложение AmneziaWG на устройствах с импортом готовых файлов.

Используй совместно существующие amneziawg-go, awg и awg-quick. Только недостающее установи
из официальных источников, сверив требуемую версию Go по go.mod выбранных исходников.
Несовместимые программы других VPN не заменяй: подбери отдельное совместимое размещение.
Получи публичные исходники проекта в свободное место на сервере либо используй проверенную
имеющуюся копию без перезаписи чужих правок. При отсутствии Git установи его штатным способом.
Для новой установки выполни из папки проверенных исходников:
sudo bash install.sh --project mybridge
Затем подставь настоящий публичный IPv4 сервера вместо ВАШ_IP:
sudo telemax-vpn --project mybridge create --public-ip ВАШ_IP --dns 1.1.1.1
sudo telemax-vpn --project mybridge add phone
sudo telemax-vpn --project mybridge add laptop

Разреши выбранный UDP-порт (сетевой вход VPN) точечно на сервере и в панели хостинга.
Если доступ к панели есть только у меня, дай одно точное действие. Сохрани прежние правила.
create создаёт отдельный совместимый AWG1. AWG2 допустим только после проверки совместимости;
подготовка существующего своего интерфейса делается штатным prepare с --project и параметрами
из GUIDE_RU.md. Не включай AWG3.1 или неизвестные параметры без подтверждённой поддержки.
Повтор add с прежним именем сохраняет доступ. При слишком длинном QR штатный результат 2
может означать готовый .conf без QR: проверь файл, объясни ограничение, не объявляй QR готовым.

По умолчанию нужны отдельные доступы phone и laptop: для каждого выдай пригодный .conf
(файл настроек подключения) и QR-код. Они находятся в закрытой папке
/etc/telemax/projects/mybridge/vpn/devices/ИМЯ/ . Закрытые ключи не печатай в отчёте.
Организуй реальное защищённое получение файлов на моих устройствах, не выдавай серверный
путь за скачиваемый файл и не публикуй их на открытом сайте или в общем чате.

Я установлю приложение из официальных источников и импортирую доступы по твоей подсказке.

4. Настрой Telegram ↔ MAX и проведи личные подтверждения

Помоги получить мои реквизиты приложения Telegram через https://my.telegram.org/apps
по https://core.telegram.org/api/obtaining_api_id . Соблюдай ограничения попыток входа.
Помоги создать отдельного бота MAX через https://business.max.ru/ по актуальным условиям
https://dev.max.ru/help/chatbots . Проверенный профиль и согласование бота могут потребовать
моих действий и ожидания; не обходи их и не обещай сроков без фактов.
Для защищённого приёма MAX нужен отдельный домен/поддомен с доверенным сертификатом на TCP 443.
Если моего домена нет, предложи временное имя sslip.io из имени проекта и IP по GUIDE_RU.md,
объясни зависимость от внешнего сервиса и получи мой выбор. Покупка домена не обязательна
для такой проверки. Проверь реальный адрес, доступность портов и получение сертификата.

Установщик уже выполнен до создания VPN: не запускай его повторно ради пересылки.
Порядок штатных команд для выбранного проекта:
sudo telemax --project mybridge configure
sudo telemax --project mybridge https
sudo telemax --project mybridge pair
sudo telemax --project mybridge login
sudo telemax --project mybridge start
sudo telemax --project mybridge status
Продолжай с первого незавершённого шага; существующий configure не перезаписывает настройки.
Для общего Caddy используй https --caddy-config с настоящим действующим файлом и при
необходимости --receiver ИМЯ_СЛУЖБЫ. Для иного приёмника https --fragment выдаёт настройку:
добавь её эквивалент в существующую программу с проверкой и плавным применением по GUIDE_RU.md.
Сохрани чужие домены, сертификаты и адреса подписок MAX. Не отключай проверку сертификатов.

configure, pair и login требуют настоящего интерактивного окна. Организуй доступный мне
личный ввод, который не записывает секреты в вывод помощника. Я сам ввожу реквизиты Telegram,
ключ бота, дополнительный пароль Telegram и одноразовый код, если площадка его запросит.
Пароль/код Telegram не запрашивай обычным сообщением и не вводи за меня.
По умолчанию используй нормальный личный интерактивный терминал со скрытым вводом.
Если выбран частный браузерный вход, сначала проверь, что на одной реальной странице
есть QR и настоящее поле скрытого ввода дополнительного пароля, его отправка в текущую
попытку входа и понятный результат. Пароль не сохраняй, поле очищай при отправке.
Сам режим login --qr-file telegram-login.png создаёт закрытую картинку, а не страницу входа
и не поле пароля. Не выдавай его за готовый браузерный вход и не создавай публичную панель.
Если личного ввода у тебя нет, дай мне одну готовую команду для настоящего личного окна
и жди только подтверждения результата, без присылки секретов. Это подтверждение аккаунта,
а не перекладывание обычной установки на подписчика.

При pair я отправляю полученную строку только своему боту в личном MAX. Перед подтверждением
сверяю ожидаемый свой аккаунт; чужого владельца не принимай, подтверждение не обходи.
При login я сканирую QR средствами Telegram на телефоне, ввожу дополнительный пароль скрыто
и подтверждаю показанный свой аккаунт. Не показывай QR и секреты в обычных отчётах/записях.
Не отправляй меня в несуществующее окно и не обещай полностью автоматический вход.
Не продолжай через неудачную привязку, вход или выпуск сертификата.

Это конкретное решение для этого инструмента: никакого автоматического сохранения вложений
в облака. Яндекс Диск, S3, Beget и Google для установки не нужны; не проси регистрацию,
ключи или настройку этих сервисов. Не запускай clouds. Проверь, что у выбранного проекта

её задачи и данные вслепую: объясни конкретное расхождение и запроси решение владельца.
Общие правила других систем не переписывай. Дополнительные архивы — только по отдельной
будущей явной просьбе, которая не входит в это поручение.

Вложения временно нужны обработке и повторам. После подтверждённой доставки сообщения
со всеми вложениями штатная очистка удаляет местные оригиналы и подготовленные файлы.

незавершённым отправкам. Тексты, очередь, сохранённый вход и связи ответов остаются.
Не удаляй их ради освобождения места. После перезапуска очистка продолжается по сохранённому
состоянию без повторной рассылки уже доставленного. Проверь результат, не только настройку.

6. Подтверди результат живыми проверками

Тестовые сообщения разрешены только в моих или явно согласованных проверочных чатах.
Не пиши клиентам и посторонним. Настоящий входящий личный тест требует согласившегося
человека или моего второго аккаунта: Codex и имитация отправителя его не заменяют.
Давай ручные действия по одному. По GUIDE_RU.md проверь:
- Новое личное входящее Telegram → MAX и «Ответить» из MAX обратно под оригинал.
- Точное @имя, упоминание выбором пользователя, ответ на моё сообщение; обычное сообщение
  без обращения не пересылается. Проверь обычную группу, большую группу и группу с темами.
- Ответ из MAX возвращается в исходную группу, под оригинал и именно в исходную тему.
- Фото с подписью, документ, видео, голосовое и кружочек в обе стороны; объясни преобразования
  и ограничения по справке, не обещай сохранение исходного качества всех форматов.
- В MAX Web файл отправляется отдельным «Ответить» на пересланную копию, без текста;
  текст — другим «Ответить» на ту же копию. Покажи мне это короткое ручное правило.
- Чужой аккаунт MAX не может отвечать в Telegram; проверяй с согласившимся участником.
- В обоих направлениях после подтверждённой доставки всех вложений местные оригиналы
  и подготовленные файлы удалены, а ответ по сохранённой связи всё ещё попадает куда нужно.
- Перезапуск только выбранной пересылки через restart, новое сообщение и ответ на старую
  копию сохраняют направление. Для очереди: stop, новое сообщение в Telegram, start,
  дочитывание без дубликатов. Компьютер выключен, пересылка продолжает работать.
- Настроен запуск после перезагрузки. Перезагрузка общего сервера — только в отдельно

Сверяй реальную доставку по обеим площадкам и очистку по состоянию сервера. Успешная команда
и состояние службы не заменяют этого. Безопасные местные проверки отказов, сохранения

обмена. Не запускай разрушительные проверки на рабочем сервере. Уместные автоматические
проверки запускай из исходников в отдельном окружении без личных настроек.
Неизвестный исход отправки сначала сверь на обеих сторонах, не повторяй вслепую.
Для разбора используй status и logs выбранного проекта, не выводя личные сведения.
