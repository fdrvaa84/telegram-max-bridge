# Telegram ↔ MAX на личном сервере

Собственный VPN (защищённое подключение к интернету) AmneziaWG и личная пересылка Telegram ↔ MAX на одном сервере.
Компьютер можно выключить: передачу выполняет сервер.
На компьютере и телефоне используется отдельное приложение AmneziaWG с импортом готовых настроек.
Серверную часть на вашем личном сервере готовит помощник по тексту ниже, каждому устройству — свой файл.
Приложение на устройстве само сервер не устанавливает.

**[Начать установку: пошаговая инструкция на русском](GUIDE_RU.md)**

[Получить личный сервер Amnezia Hosting](https://my.amnezia.host/aff.php?aff=158)
— партнёрская ссылка автора.

[Один готовый текст для Codex](SETUP_PROMPT_RU.md)
— скопируйте весь блок, заполните доступ к серверу в его начале и отправьте одним сообщением.
Помощник сам выполнит установку; вы по его подсказкам подтвердите входы и проверите результат.
Устанавливать сервер вручную командами из справки ниже подписчику не нужно.

На существующем сервере создаётся отдельный именованный проект. На одном сервере могут работать
несколько таких проектов и другие программы. Каждому проекту нужны свой бот MAX и домен.
Действующие VPN, настройки и доступы сохраняются. Новый сервер нужен только читателю без подходящего сервера.

- В MAX приходят личные входящие Telegram, а из групп — упоминания владельца и ответы на его сообщения.
- «Ответить» под копией в MAX отправляет ответ от вашего аккаунта в исходный чат Telegram, под исходное сообщение, в ту же тему.
- Ответы разрешены только привязанному владельцу MAX. Привязка требует одноразового кода и подтверждения в личном окне сервера.
- Поддерживаются текст, фото, документы, видео, голосовые, кружочки и подписи с [описанными преобразованиями](GUIDE_RU.md#форматы-и-ограничения).
- Очередь, вход и связь сообщений сохраняются после перезапуска. Неопределённая отправка останавливается, чтобы не создавать дубликаты.
- После подтверждённой доставки сообщения со всеми вложениями местные оригиналы и подготовленные файлы автоматически удаляются. При ошибке или неопределённом результате они сохраняются для повтора. Очередь, тексты и связи ответов остаются. Облачные архивы в этом пути не подключаются. Дополнительные хранилища — только по отдельной будущей явной просьбе.

Для постоянного приёма MAX нужен отдельный адрес с подтверждением подлинности.
Помощник использует уже переданный подходящий домен (имя адреса в интернете), иначе сам выбирает
бесплатное имя sslip.io по адресу сервера без покупки и отдельного согласования. Он проверяет
соответствие имени адресу сервера, доступность из интернета и получение сертификата, а в результате
объясняет зависимость имени от внешнего сервиса: управление им и постоянная доступность не гарантированы,
при смене адреса сервера имя потребуется заменить.
Основной вариант VPN — AmneziaWG; помощник выделяет ему отдельное свободное подключение.
Настройку ведёт Codex. Подтверждения аккаунтов и действия на телефоне выполняет владелец; полностью автоматический вход не обещается.

## Техническая справка для помощника

Следующие команды выполняет помощник на сервере. Основной путь подписчика — инструкция и один готовый текст выше.

### Выбор проекта

В примерах имя проекта `mybridge`. Замените его своим именем во всех командах.
После получения исходников выполните на выбранном сервере

```sh
sudo bash install.sh --project mybridge
sudo telemax-vpn --project mybridge create --public-ip ВАШ_IP --dns 1.1.1.1
sudo telemax --project mybridge configure
sudo telemax --project mybridge https
```

VPN использует существующие `amneziawg-go`, `awg`, `awg-quick`. Помощник устанавливает только
недостающие программы из официальных источников. Создание выбирает отдельные ключи,
интерфейс, свободную подсеть и UDP-порт. Выдача устройства показана ниже.
Если общий Caddy уже работает, используйте `https --caddy-config /etc/caddy/Caddyfile`.
Для другого приёмника `https --fragment` готовит настройку своего домена для добавления
в действующий приёмник. Порядок привязки и входа приведён в руководстве.
Второй проект создаётся теми же командами с другим именем, ботом и доменом.
Старая установка сохраняет команды `sudo telemax` и `sudo telemax-vpn` без выбора проекта,
прежние пути и данные. Её обновляют запуском нового `install.sh --update` без `--project`.

## Отдельный доступ для каждого устройства

После подготовки VPN помощник выполняет на сервере команды выдачи для телефона и компьютера.

```sh
sudo telemax-vpn --project mybridge add phone
sudo telemax-vpn --project mybridge add laptop
```

Поддерживаются проверенные параметры AWG1 и AWG2. Команда создаёт закрытые `.conf` и QR-код с одинаковыми настройками. Повтор с тем же именем
возвращает прежний доступ. Для другого устройства используйте другое имя, например `laptop`.
Установка программы выдачи, проверка параметров сервера и защищённое получение файлов
описаны в [руководстве](GUIDE_RU.md#выдача-доступов-командой).

## Что проверено

Автоматические проверки используют только вымышленные сообщения и поддельные ответы площадок:
проверяют направления, темы, фильтры, сохранение, повторные события, паузу Telegram,
неполное чтение, чужого отправителя, неопределённую отправку и обычный запуск программы.
Отдельно проверяются преобразования настоящих синтетических аудио и видео через ffmpeg.

Результат чистой установки и границы проверки указаны в конце [инструкции](GUIDE_RU.md#что-проверено-перед-передачей).
Установка на новом оплаченном VPS и живой обмен с собственными учётными данными подписчика
не заменяются этими проверками. До завершения раздела «Живая проверка» установка не подтверждена.
