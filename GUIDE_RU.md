# Пошагово: свой VPN и Telegram ↔ MAX

В результате на вашем сервере появится отдельный проект: он даёт VPN вашим устройствам и пересылает
нужные входящие Telegram в ваш бот MAX. Компьютер для постоянной работы не нужен.
Ответ из MAX через «Ответить» уйдёт от вашего аккаунта Telegram в исходный чат и тему.

Вы вводите только свои реквизиты. Никому не отправляйте пароль сервера, ключ бота,
реквизиты приложения, QR-код входа и сохранённый вход Telegram.

[Получить личный сервер Amnezia Hosting](https://my.amnezia.host/aff.php?aff=158)
— партнёрская ссылка автора.

[Установить с помощником в командной строке](SETUP_PROMPT_RU.md)
— готовый текст для Codex CLI, Claude Code и других помощников.

## До начала

Потребуются Telegram и MAX, телефон с уже работающим Telegram,
сервер с вашим правом установки отдельных проектов и собственный домен либо поддомен. Для создания бота MAX заранее нужен
верифицированный профиль самозанятого, ИП или организации — [официальное условие](https://dev.max.ru/help/chatbots).

Существующий сервер с другими приложениями подходит. Сохраняйте их работу, данные и доступы.
Ни сервер, ни домен эта программа не покупает. Цены и доступность смотрите у поставщиков.

## 1. Выберите существующий сервер или получите новый

1. Если VPS уже есть, используйте его. Если сервера нет, откройте [панель Amnezia Hosting для заказа сервера](https://my.amnezia.host/aff.php?aff=158)
   (партнёрская ссылка) и [официальную инструкцию Hosting](https://wiki.amnezia.host/vpn-setup.html). создайте **личный VPS** — постоянно работающий компьютер в интернете.
2. Основной путь этой инструкции — **Ubuntu 24.04, x86-64, KVM и публичный IPv4**.
   Поддерживаются также Ubuntu 22.04 и Debian 12/13. Не выбирайте контейнерный сервер OpenVZ/LXC.
3. [Официальные требования Amnezia](https://docs.amnezia.org/documentation/supported-linux-os-for-vps/)
   допускают 1 ГБ памяти для самого VPN. Для совместной работы с перекодированием видео
   мы рекомендуем начать с **2 ядер, 4 ГБ памяти и 40 ГБ диска**: это инженерная оценка,
   а не измеренная гарантия. Диск нужен для временной обработки, очереди неотправленных файлов и незавершённых архивных копий.
   После подтверждённой доставки и завершения включённых архивных копий учтённые вложения удаляются автоматически.
   Одновременная обработка тяжёлого видео и VPN может требовать больше ресурсов.
4. Сохраните адрес сервера, имя пользователя и пароль либо ключ из панели в своём менеджере паролей.
   Не переустанавливайте существующий сервер ради этой инструкции.

## 2. Установите отдельное приложение AmneziaWG на устройства

На компьютер и телефон установите **AmneziaWG** по ссылкам для вашей системы из
[официальной инструкции приложения](https://docs.amnezia.org/documentation/instructions/use-amneziawg-app/).
Там есть ссылки для Windows, Mac, iPhone и Android. Загружайте приложение из указанных
официальных источников и разрешите добавление VPN, когда система попросит.
Для своего сервера используйте раздел Self-hosted. Раздел Premium относится к другой услуге.

Сначала в отдельном проекте вашего сервера нужно подготовить VPN — защищённое подключение к интернету.
Приложение AmneziaWG на устройстве импортирует готовые настройки. Сам сервер оно не устанавливает.

## 3. Подготовьте VPN на сервере и импортируйте подключение

Основной путь — [готовый текст для помощника](SETUP_PROMPT_RU.md).
Помощник готовит серверную часть AmneziaWG **в отдельном проекте на вашем VPS** через
SSH — защищённое подключение к серверу. На компьютере серверные службы устанавливать не нужно.
Он сначала использует уже установленные официальные программы `amneziawg-go`, `awg`, `awg-quick`.
Недостающие программы собираются по официальной инструкции без замены существующего VPN.
Сначала подключитесь к выбранному серверу и установите сам инструмент.
Имя `mybridge` — пример. Выберите своё имя из 1–20 строчных латинских букв, цифр и дефисов,
начиная с буквы, и используйте его во всех командах. Второй проект получает другое имя.
На компьютере откройте терминал и подключитесь командой `ssh root@АДРЕС_СЕРВЕРА`,
подставив свои адрес и пользователя. Сверьте ключ сервера по доверенному источнику.
Все следующие команды выполняются в окне сервера. Получите публичные исходники и установите проект

```sh
sudo apt-get update
sudo apt-get install -y git
sudo git clone https://github.com/fdrvaa84/telegram-max-bridge.git /usr/local/src/telegram-max-bridge
sudo bash /usr/local/src/telegram-max-bridge/install.sh --project mybridge
```

Если копия исходников уже есть, используйте её после проверки происхождения и незаконченных правок.
Если выбранный проект уже установлен, продолжайте первый незавершённый шаг. Готовые настройки
и вход сохраняются. Пересылка включается после личной настройки в пунктах 7–9.
Затем помощник использует имеющиеся программы AmneziaWG или устанавливает недостающие по
официальной инструкции ниже. После этого создайте отдельный VPN

```sh
sudo telemax-vpn --project mybridge create --public-ip ВАШ_ПУБЛИЧНЫЙ_IP --dns 1.1.1.1
```

Подставьте проверенный публичный IPv4 сервера. Команда создаёт совместимый AWG1 VPN,
сохраняет собственные ключи и выбирает свободные интерфейс, подсеть и UDP-порт.
Повтор с теми же параметрами продолжает прежнюю подготовку, конкурирующие создания ждут друг друга.
Порт из результата разрешите в панели вашего провайдера. Правила сервера касаются этого проекта.
Здесь настроен выход IPv4. IPv6 направляется в туннель без выхода, поведение блокировки обхода
нужно проверить в приложении. Полный работающий IPv6 этим подготовщиком не заявляется.

1. Передайте помощнику готовый текст. Покупку, личный ввод секретов и действия
   в приложениях выполняете вы. Пароли и настройки подключения в чат не отправляйте.
2. Получите для каждого устройства свой закрытый файл `.conf` — файл настроек подключения.
   Помощник должен сверить возможности установленного приложения и серверной части.
   Новейшие параметры AWG3.1 нельзя включать без подтверждения их поддержки приложением.
3. **На компьютере** откройте AmneziaWG и импортируйте предназначенный ему файл.
   **На телефоне** откройте AmneziaWG, добавьте подключение из своего файла или
   отсканируйте QR-код настроек, если этот способ поддерживается вашей версией приложения.
   Такой QR-код тоже секретный. Передавайте файлы только между своими устройствами защищённым способом.
4. На время проверки отключите другое VPN-подключение на устройстве, сохранив его настройки.
   Включите новое подключение. Проверьте сайты, Telegram и обычный интернет с телефона
   через мобильную сеть, затем с компьютера. Помощник сверяет реальный обмен на сервере.
   Надпись «подключено» и пустое созданное подключение на сервере этого не подтверждают.
5. Отдельно проверьте IPv4 и IPv6 — два вида интернет-адресов. Полный IPv6 можно считать
   работающим только после проверки трафика. Если он недоступен, помощник должен явно
   указать ограничение и исключить обход VPN через IPv6, сохранив остальные подключения.

AmneziaWG использует UDP — вид сетевого соединения. Его порт должен быть разрешён на сервере
и в панели Hosting. TCP 443 остаётся для MAX, TCP 80 — для получения сертификата.
Установщик пересылки размещает программы. Отдельный VPN создаёт команда `create` выше. Установка одного серверного файла программы
или создание пустого сетевого подключения ещё не дают работающий интернет.

### Выдача доступов командой

После `create` выбранный проект готов к выдаче устройств. Для существующей отдельной
подготовленной конфигурации вместо создания допустима прежняя команда `prepare` с выбором проекта.
Она проверяет работающий интерфейс и сохраняет его параметры, ключи не заменяет.
Нельзя привязывать два проекта к одному интерфейсу, если требуется отдельный VPN каждого.
Нужны Python 3, `iproute2`, `qrencode`, `iptables`, официальные `awg`, `awg-quick` и `amneziawg-go`.
Установщик ставит обычные зависимости и программу выдачи. Недостающие программы Amnezia
помощник получает по [официальной инструкции](https://docs.amnezia.org/documentation/instructions/install-amneziawg-go/),
проверяя версию Go по выбранным исходникам и сохраняя уже работающие программы.

Выдача поддерживает AWG1 и AWG2, причём AWG2 выбирается после проверки поддержки
установленным приложением на каждом устройстве. Параметры AWG3.1 требуют отдельной проверки
совместимости и останавливают автоматическую выдачу. Сервер с ними сохраняется как есть.
Справочники параметров и формата приведены в [официальных исходниках tools](https://github.com/amnezia-vpn/amneziawg-tools)
и [описании AmneziaWG](https://docs.amnezia.org/documentation/amnezia-wg/).

Дальше каждый доступ создаётся одной командой на сервере.

```sh
sudo telemax-vpn --project mybridge add phone
sudo telemax-vpn --project mybridge add laptop
```

Имя состоит из латинских букв, цифр, дефисов и подчёркиваний, до 15 символов.
Повторное имя возвращает сохранённые ключи и адрес. Разные имена создают отдельные доступы.
Одновременные команды ждут друг друга. Программа резервирует адреса из постоянных и
действующих настроек, дописывает одного клиента и проверяет его в обоих местах.
Папки закрываются правами `700`, файлы настроек и QR-коды — `600`, то есть доступны только
владельцу сервера. По умолчанию это закрытая папка `/etc/telemax/projects/mybridge/vpn`.

Команда выводит только расположение файлов. Для `phone` это
`/etc/telemax/projects/mybridge/vpn/devices/phone/phone.conf` и `/etc/telemax/projects/mybridge/vpn/devices/phone/phone.png`.
Получите оба файла по SFTP — защищённой передаче файлов через ваше подключение к серверу,
либо командой ниже **в личном терминале вашего компьютера**. Подставьте свой адрес
подключения вместо `MY_SERVER`, предварительно сверив ключ сервера. Нужен уже настроенный
вход и право выполнять `sudo` без запроса пароля для этого чтения.

```sh
umask 077
mkdir -p "$HOME/telemax-private"
chmod 700 "$HOME/telemax-private"
ssh -T MY_SERVER 'sudo -n cat /etc/telemax/projects/mybridge/vpn/devices/phone/phone.conf' > "$HOME/telemax-private/phone.conf.part" &&
  test -s "$HOME/telemax-private/phone.conf.part" &&
  mv "$HOME/telemax-private/phone.conf.part" "$HOME/telemax-private/phone.conf"
ssh -T MY_SERVER 'sudo -n cat /etc/telemax/projects/mybridge/vpn/devices/phone/phone.png' > "$HOME/telemax-private/phone.png.part" &&
  test -s "$HOME/telemax-private/phone.png.part" &&
  mv "$HOME/telemax-private/phone.png.part" "$HOME/telemax-private/phone.png"
chmod 600 "$HOME/telemax-private/phone.conf" "$HOME/telemax-private/phone.png"
```

Проверьте успешное завершение обеих команд и наличие непустых файлов. При отказе `sudo`
помощник организует закрытую передачу вашему пользователю сервера через SFTP.
Откройте картинку обычным просмотрщиком на своём компьютере и отсканируйте её в AmneziaWG
на телефоне. Также можно передать `.conf` на телефон личным защищённым способом и выбрать
импорт файла в AmneziaWG. На компьютере импортируйте его собственный `.conf`.
Оба файла позволяют пользоваться вашим VPN, храните их как пароль. Публичные сайты,
веб-серверы, чаты и журналы для передачи этих файлов не подходят.

Если настройки слишком длинные для QR-кода, команда сохраняет и подключает рабочий `.conf`,
показывает предупреждение и завершает работу с кодом `2`. Импортируйте этот файл.
Повтор команды с тем же именем сохраняет доступ и снова пробует построить QR-код.
При ошибке добавления программа удаляет своё незавершённое подключение и возвращает
постоянные настройки. После обрыва повторите `add` с прежним именем. При обнаружении
посторонних изменений программа сохраняет закрытую запись восстановления и просит
помощника проверить сервер. Работающие подключения при выдаче продолжают работать.

**Точка продолжения.** Если помощник уже настроил VPN и пересылку полностью,
переходите к разделу [«Живая проверка»](#10-живая-проверка), продолжая с первого
непроверенного действия. Повторять настройку, привязку MAX и вход Telegram не нужно.
Если готов только VPN, продолжайте с пункта 4 ниже.

## 4. Получите свои реквизиты приложения Telegram

1. Откройте [my.telegram.org/apps](https://my.telegram.org/apps) при доступном Telegram.
2. Войдите своим номером. Код обычно приходит в Telegram, а не по SMS.
3. Выберите API development tools. Создайте личное приложение: например, название «Personal Bridge»,
   короткое имя из латинских букв. Заполните обязательные поля формы; не используйте чужие реквизиты.
4. Сохраните **api_id** (номер приложения) и **api_hash** (секрет приложения).
   Эти значения нужны программе для входа от вашего аккаунта. В публичный код их вставлять не надо.

[Официальное описание Telegram](https://core.telegram.org/api/obtaining_api_id).
Если Telegram временно ограничил вход или создание приложения, дождитесь срока из его сообщения,
не повторяйте попытки подряд и не обходите ограничения.

## 5. Создайте отдельного бота MAX

1. Откройте [MAX для бизнеса](https://business.max.ru/) и свой подтверждённый профиль.
2. В разделе «Чат-боты» создайте бота, заполните карточку и завершите требуемое платформой
   согласование/публикацию. Не используйте бот, подключённый к другой программе.
3. В настройках скопируйте **токен** — секретный ключ бота. Держите его в менеджере паролей.
4. Откройте своего бота в приложении MAX и нажмите «Начать». Пока он не отвечает — это нормально.

[Официальные шаги и получение ключа](https://dev.max.ru/help/chatbots).

## 6. Подготовьте публичный защищённый адрес MAX

Для постоянной работы MAX присылает события на ваш сервер через **Webhook** — защищённый
адрес приёма сообщений. Нужен HTTPS с доверенным сертификатом на **TCP 443**.
Опрос событий Long Polling официально предназначен для разработки и тестирования и здесь не используется.
[Требования MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions),
[описание событий](https://dev.max.ru/docs-api/use-cases/event-notifications).

1. Используйте свой домен у регистратора. Можно выделить поддомен, например `bridge.example.org`
   (**это пример**, замените его своим именем).
2. В управлении доменом создайте запись **A** для выбранного имени → публичный IPv4 вашего сервера.
   Уберите запись AAAA для этого имени, если IPv6 не настроен. Отключите промежуточное проксирование
   вроде «оранжевого облака»: на первом запуске нужен прямой адрес сервера.
3. В панели Hosting разрешите входящие **TCP 80 и TCP 443**. Первый нужен для автоматического
   сертификата, второй — для MAX. Не закрывайте порт подключения к серверу и UDP-порт VPN.
   Если вы сами включали дополнительный межсетевой экран в Linux, разрешите эти два порта и там.
   Наш установщик не меняет правила доступа.
4. Подождите обновления адреса домена (иногда это занимает часы).
   На компьютере можно проверить, заменив пример:

   ```sh
   nslookup bridge.example.org
   ```

   В ответе должен быть публичный IPv4 вашего сервера.

Бесплатный домен в этой инструкции не обещается: проверенного бесплатного варианта здесь нет.
Если своего домена ещё нет, приобретите его самостоятельно либо выделите поддомен уже имеющегося.
Получение сертификата выполнит отдельная команда ниже через Caddy — программу для защищённого соединения.

## 7. Настройте установленный проект

Инструмент с выбранным именем уже установлен в пункте 3. Продолжайте в окне сервера.
Если подключение закрыли, откройте его командой `ssh root@АДРЕС_СЕРВЕРА`, подставив свой
адрес и пользователя. В примерах выбран `mybridge`, используйте своё имя во всех командах.
Повторять установку ради настройки пересылки не требуется.

Установщик также переносит публичный корневой сертификат для исходящего соединения с MAX
(`platform-api2.max.ru`). Он взят с [официального сайта](https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt),
описанного на [Госуслугах](https://www.gosuslugi.ru/crt); адрес API указан в
[документации MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions).
Программа перед использованием проверяет SHA256 отпечаток сертификата в формате DER:
`d26d2d0231b7c39f92cc738512ba54103519e4405d68b5bd703e9788ca8ecf31`.
Ручного добавления не нужно: системные доверенные сертификаты сохраняются, проверка подлинности
и имени сервера включена. Дополнительное доверие действует только внутри программы, включая
привязку, подписку, её отмену и проверку защищённого адреса.
Это **не сертификат вашего домена**: для входящих сообщений MAX по-прежнему нужен собственный
публичный адрес с сертификатом, который получает Caddy на следующем шаге.

Введите свои реквизиты:

```sh
sudo telemax --project mybridge configure
```

Номер приложения, секрет Telegram и ключ MAX вводятся скрыто — это нормально, даже «звёздочек» нет.
Домен вводите без `https://`, порта и пути. Настройки сохраняются с доступом только для служебного
пользователя и администратора сервера. Повторный `configure` не перезаписывает готовые настройки.

Включите защищённый адрес:

```sh
sudo telemax --project mybridge https
```

При свободном общем входе команда создаёт общий приёмник для доменов проектов.
При уже работающем приёмнике добавьте маршрут по разделу «TCP 443 или 80 занят» ниже.
Для общего Caddy используйте `https --caddy-config /etc/caddy/Caddyfile`.
Подождите минуту. Не вводите чужие домены и не отключайте проверку сертификатов.

## 8. Безопасно привяжите себя в MAX

```sh
sudo telemax --project mybridge pair
```

Команда проверит защищённый адрес и зарегистрирует его в MAX, затем покажет строку `/bind ...`.
За пять минут отправьте **всю строку** своему боту в **личном диалоге MAX**.
Не отправляйте её в группу, другим людям или в поддержку.

Вернитесь в окно сервера. Убедитесь, что запрос пришёл от вашего аккаунта, и напишите
`ПОДТВЕРЖДАЮ`. После этого чужие пользователи бота не смогут отправлять ответы в Telegram.
Повторно захватить уже привязанный аккаунт этой командой нельзя.
Если время истекло, запустите команду снова: старый код работать не будет.

## 9. Войдите в Telegram по QR-коду

```sh
sudo telemax --project mybridge login
```

В окне сервера появится QR-код. На телефоне откройте Telegram → Настройки → Устройства →
Подключить устройство и отсканируйте код. Это именно сканер **в Telegram**, не камера телефона.
Расширьте окно сервера, если рисунок перенёсся по строкам.

Если Telegram просит второй пароль, введите ваш облачный пароль в окне сервера: ввод скрыт.
Программа его не сохраняет. При истёкшем QR-коде повторите команду, не делайте много попыток подряд.
Проверьте показанный аккаунт и напишите `ПОДТВЕРЖДАЮ`.

Запустите постоянную передачу:

```sh
sudo telemax --project mybridge start
sudo telemax --project mybridge status
```

Должны быть: владелец MAX привязан, вход Telegram сохранён, передача включена, служба работает,
запуск после перезагрузки включён. Старую переписку программа массово не загружает:
начинает с момента первого включения; последующий перерыв дочитывает с сохранённой позиции.

## 10. Живая проверка

Используйте только личные проверочные чаты и людей, которые согласились помочь.

1. Попросите помощника отправить вам **новое личное сообщение** в Telegram. Подождите около минуты.
   Оно должно прийти в ваш бот MAX с названием источника и именем отправителя.
2. В MAX нажмите **«Ответить» именно под этой копией**, напишите ответ.
   Проверьте, что он пришёл от вашего аккаунта в исходный диалог Telegram под исходное сообщение.
3. В проверочной обычной группе попросите написать ваше точное `@имя`, затем упомянуть вас
   выбором пользователя и ответить на ваше сообщение. Все три обращения должны прийти в MAX.
   Обычное сообщение группы без обращения приходить не должно.
4. Повторите в большой группе Telegram и в группе с темами. Ответьте из MAX и проверьте исходную тему.
5. Проверьте фото с подписью, документ, короткое видео, голосовое и кружочек в обе стороны.
   При видео из MAX выберите предложенный вариант «Видео» или «Кружочек».
6. Попросите другой аккаунт MAX ответить боту: сообщения в Telegram от него появляться не должны.
7. Перезапустите только передачу и отправьте ещё одно новое сообщение:

   ```sh
   sudo telemax --project mybridge restart
   sudo telemax --project mybridge status
   ```

   Старый ответ не должен отправиться повторно. Ответ на ранее полученную копию должен по-прежнему работать.
8. Выключите компьютер. Проверьте с телефона новое сообщение и ответ.
   Перезагрузку общего сервера проверяйте только в подходящее для всех его служб время.
   Пока она не пройдена, работу после перезагрузки именно на вашем VPS считайте непроверенной.

## Ежедневные команды

```sh
sudo telemax --project mybridge status       # состояние и свободное место без содержимого переписок
sudo telemax --project mybridge logs         # безопасные сообщения за последний час
sudo telemax --project mybridge restart      # перезапуск передачи, VPN продолжает работать
sudo telemax --project mybridge subscribe    # проверить адрес и восстановить подписку MAX
sudo telemax --project mybridge update       # установить проверенную новую программу, сохранив вход и очередь
sudo telemax --project mybridge rollback     # вернуть прежнюю программу после неудачного обновления
sudo telemax --project mybridge stop         # остановить передачу и выключить её автозапуск
```

После остановки для возобновления выполните `sudo telemax --project mybridge start`.
Команда остановки сначала выключает службу; если сеть не дала отписаться в MAX, передача всё равно
остановлена, а ключ бота и вход не удалены. Адрес приёма остаётся установленным для будущего включения.

MAX может снять подписку после длительной недоступности адреса; после устранения причины выполните
`sudo telemax --project mybridge subscribe` и живую проверку. Сообщения за время снятой подписки могут быть потеряны:
MAX не обещает бесконечное хранение событий для бота.

## Где хранятся вход и сообщения

На вашем сервере в `/var/lib/telemax-projects/mybridge`: закрытые настройки и сохранённый вход Telegram, очередь,
связи копий и ещё нужные для отправки оригиналы вложений. Текст сообщений и подписи хранятся в очереди. Они также остаются
на площадках в соответствии с их правилами. Это копирование через бота, а не сквозное шифрование
между Telegram и MAX. Администратор сервера имеет доступ к данным.

Секреты не передаются автору инструмента. Обычные журналы не содержат текстов, номеров, ключей,
адресов вложений и названий чатов. Вход и данные не попадают в обновления программы.
После подтверждённой доставки сообщения со всеми вложениями программа автоматически удаляет свои местные оригиналы и подготовленные файлы в обоих направлениях. Загрузка файла на площадку сама по себе ещё не подтверждает доставку. При ошибке, незавершённой отправке или неопределённом результате файлы сохраняются. Тексты, очередь и связи ответов с исходными чатами, группами и темами остаются.

После перезапуска очистка продолжается по сохранённому состоянию. Это относится и к ранее успешно доставленным вложениям, для которых сохранился учёт оригинала. Повторная рассылка для очистки не требуется. Файл остаётся, пока он нужен другой незавершённой отправке или включённому облачному копированию. Очистка ограничена учтёнными файлами этой пересылки. Следите за свободным местом при накоплении неудачных отправок.

Чтобы отозвать доступ: остановите передачу, затем в Telegram → Настройки → Устройства завершите
сеанс этого сервера. При необходимости перевыпустите ключ бота MAX в его настройках.
Не пытайтесь просто удалить программу, оставляя активный вход Telegram.
Подробнее — [безопасность и восстановление](SECURITY.md).

## Две независимые облачные копии — необязательно

По умолчанию облачное копирование выключено. Местные оригиналы хранятся до подтверждённой доставки всех вложений и затем удаляются. Дальнейшая доступность доставленных файлов зависит от правил Telegram и MAX.
Если они нужны, подготовьте два частных S3-совместимых хранилища **у разных поставщиков**,
с ключами, разрешающими запись и обратное чтение. Например, хранилище с доступом по S3 у первого
поставщика и у второго; общий архив автора не используется. Яндекс Диск напрямую не подключён:
здесь реализован переносимый вариант через два S3-совместимых направления.

```sh
sudo telemax --project mybridge clouds
sudo telemax --project mybridge restart
sudo telemax --project mybridge status
```

Введите адрес каждого хранилища, имя частного контейнера (bucket), регион и собственные ключи.
Ключи вводятся скрыто. Нельзя указывать два одинаковых адреса. Независимость поставщиков проверяете вы.
Программа находит местные оригиналы, ставит две независимые задачи и повторяет неудачные записи
после перезапуска. Каждую копию считывает обратно, сравнивает размер и SHA256 — цифровой отпечаток
содержимого. Только после этого показывает «проверено». Отдельно переносит имя и связь с сообщением.
Одна недоступная площадка не мешает второй. При включённом копировании местный оригинал удаляется после подтверждённой доставки всех вложений и проверки обеих облачных копий. Незавершённые облачные задачи сохраняют местный файл до завершения. Облачные копии остаются в ваших хранилищах.

Это копии **вложений**, а не резерв всей установки: вход Telegram, ключи, тексты очереди и связь копий
для восстановления всего сервера нужно отдельно сохранять закрытой резервной копией, как описано ниже.
Тариф облака может учитывать обратное скачивание. Совместимость с вашими поставщиками обязательно
проверьте на личном тестовом документе; реальных облачных учётных данных в автоматических проверках нет.

## Форматы и ограничения

| Что присылают | Как передаётся |
|---|---|
| Текст | Обычный текст без сохранения исходного оформления. Длинное входящее делится на части, каждая сохраняет возможность ответа. Ответ MAX — до 4096 знаков. |
| Фото | В MAX и обратно — JPEG с ограничением стороны 2560. Это может изменить качество и убрать метаданные. Местный оригинал хранится до выполнения условий очистки из раздела выше. |
| Документ | Как файл с именем; содержимое не перекодируется. |
| Видео | В MAX — MP4 H.264/AAC. В Telegram — обычное видео после выбора. |
| Голосовое Telegram | В MAX — аудиозапись AAC/M4A с пояснением. |
| Аудио/голосовое MAX | В Telegram — голосовое OGG/Opus. Музыкальное аудио MAX также станет голосовым. |
| Кружочек Telegram | В MAX — обычное видео MP4 с пометкой «Кружочек». Отдельный круглый формат MAX не обещается. |
| Видеоответ MAX → кружочек | По явному выбору: до 60 секунд, квадрат 384×384, края обрезаются. Длиннее минуты не обрезается молча — отправка останавливается. |
| Подпись | Передаётся текстом. Для кружочка или слишком длинной подписи в Telegram — отдельным ответом под тот же оригинал. |

Фотоальбомы могут приходить отдельными сообщениями. Порядок отдельных вложений не обещается как
единый альбом. Пересылка не синхронизирует прочтение, удаления и правки уже скопированных сообщений.
Имя автора показывается текстом, ответ всегда отправляется **от вашего** аккаунта.

Местный предел одного вложения — 250 МиБ, но лимиты аккаунтов и обеих площадок могут быть меньше.
Перекодирование ограничено тремя минутами; большой или сложный файл может не пройти.
Не поддерживаются секретные чаты, исчезающие/платные вложения, опросы, контакты, геолокация,
стикеры, реакции и содержимое с запретом пересылки. Служебные сообщения, уведомления входа,
боты и каналы не копируются. Это не способ обхода защиты чужих чатов.

При неизвестном результате отправки программа **останавливает эту отправку**: она могла уже дойти.
Автоматической команды «повторить всё» нет. Сверьте обе стороны вручную; при необходимости
ответьте заново, понимая риск дубликата. Программа не обещает безусловной доставки ровно один раз
при сетевом обрыве, удалении исходного сообщения или ограничениях площадок.

## Типичные проблемы

**Первый вход не подтверждается.** Телефон должен открывать Telegram; сначала проверьте VPN.
Сканируйте QR внутри Telegram → Устройства. Расширьте окно сервера. Истёкший код обновляется новым
запуском `sudo telemax --project mybridge login`. Во время повторного входа останавливается выбранный проект, прежнее состояние запуска восстанавливается. Для первого запуска нужен `sudo telemax --project mybridge start`.

**Запрашивается второй пароль.** Это облачный пароль Telegram, а не пароль сервера и не код SMS.
Восстановление делайте в официальном Telegram. Не отправляйте пароль в чат с ботом.

**В AmneziaWG нет установки сервера.** Серверную часть готовит помощник по пункту 3.
После этого импортируйте свой файл подключения или QR в приложение AmneziaWG.

**VPN подключается, но связи нет.** Отключите остальные VPN на устройстве и попробуйте снова.
Проверьте отдельный доступ устройства и дату/время. Не меняйте маршруты сервера наугад.

**Telegram просит подождать.** Программа ограниченно повторяет безопасное чтение после назначенной
паузы. Неудачное чтение не считается пустым чатом, сохранённая позиция не перескакивает вперёд.
Отправка при явной просьбе Telegram подождать откладывается. Ограничения самого аккаунта программа не снимает.

**Адрес MAX недоступен / не привязывается.** Проверьте домен через `nslookup`, разрешение TCP 80/443,
прямой адрес без промежуточного прокси и завершённый выпуск сертификата. В браузере откройте
`https://ВАШ_ДОМЕН/health` во время `sudo telemax --project mybridge pair` или работы службы: должен быть ответ с `ready: true`.
Проверка из самого сервера не заменяет доступность снаружи. Повторите `pair`, если ещё не привязались,
или `subscribe`, если уже работаете. Не используйте самоподписанный сертификат.

**TCP 443 или 80 занят.** Используйте общий приёмник. Для работающего Caddy выполните
`sudo telemax --project mybridge https --caddy-config /etc/caddy/Caddyfile`.
Команда добавляет только отдельный файл домена через `import`, проверяет всю настройку
и плавно применяет её. При отказе возвращает прежний текст.
Если у общего Caddy отключено управление через `admin off`, автоматический `reload` недоступен.
Используйте `https --fragment`. Для Caddy, запущенного через `caddy run --config` без `--resume`
и последующих изменений через управляющий интерфейс, после проверки настройки применим
`sudo systemctl kill --kill-who=main --signal=SIGUSR1 ИМЯ_СЛУЖБЫ`, затем проверьте новый домен.
Если эти условия отсутствуют, нужен штатный способ плавного применения самого приёмника.
[Условия применения и сигналы Caddy](https://caddyserver.com/docs/command-line#signals). Чужие домены и сертификаты сохраняются.
Укажите реальный файл действующей службы, при другом имени службы добавьте `--receiver ИМЯ`.
Для Nginx или другого приёмника выполните `sudo telemax --project mybridge https --fragment`.
Полученный пример для Caddy содержит точные домен и местный порт проекта. В другом приёмнике
создайте отдельный HTTPS-домен с действующим сертификатом, направьте только `/webhook` и `/health`
на указанный `http://127.0.0.1:ПОРТ`, остальные пути возвращают 404. Например, внутри собственного
блока `server` Nginx с уже настроенными `listen 443 ssl`, `server_name` и сертификатом

```nginx
location = /webhook { proxy_pass http://127.0.0.1:ПОРТ; }
location = /health { proxy_pass http://127.0.0.1:ПОРТ; }
location / { return 404; }
```

Подставьте порт из созданного примера, добавьте домен в действующий приёмник, проверьте
`sudo nginx -t` и выполните `sudo systemctl reload nginx`. Выпуск сертификата выполняйте
уже используемым способом сервера. Автоматическое изменение произвольного приёмника
не поддерживается. Если TCP 443 занят программой без маршрутизации HTTPS по доменам,
такой приём через этот же IP:443 технически недоступен до настройки совместимого общего входа.
Службы и подключения при этом продолжают работать.

**Защищённый адрес установился, но сертификата нет.** После исправления адреса и доступа Caddy повторит
получение сам. Для проверки его состояния: `sudo systemctl status telemax-web --no-pager`.
Подробный журнал `sudo journalctl -u telemax-web --since '15 minutes ago' --no-pager` смотрите только сами:
в нём может быть ваш домен, не публикуйте его без очистки.

**Из группы ничего не приходит.** Проверьте новое обращение именно к вашему аккаунту,
членство в группе и запрет пересылки. Чужие обращения не пересылаются. Закрытую пересылку
и исчезающие сообщения программа пропускает, а не пытается обойти.

**Фото/файл/видео не прошло.** Проверьте список форматов и размер. Попробуйте обычное короткое видео
или документ меньшего размера. После явно отклонённого формата отправьте новый ответ.
При «исход неизвестен» сначала проверьте, не дошёл ли прежний.

**После выключения компьютера всё остановилось.** Убедитесь, что установка выполнена в окне
подключения к серверу, а не на компьютере. Проверьте `sudo telemax --project mybridge status`.

**После долгого простоя MAX перестал принимать ответы.** Поднимите защищённый адрес,
выполните `sudo telemax --project mybridge subscribe` и проверьте новое сообщение. Старые события MAX могли истечь.

**Свободное место заканчивается.** Остановите передачу, увеличьте диск сервера или сделайте
проверенную закрытую резервную копию. Автоочистка удаляет учтённые успешно доставленные вложения после завершения всех потребителей. Проверьте неудачные отправки и незавершённые облачные копии, которые удерживают файлы. Сохраняйте очередь и вход при освобождении места.

## Обновление и восстановление

`sudo telemax --project mybridge update` берёт новую программу из этого репозитория, устанавливает зависимости в отдельное
место и выполняет проверки до переключения. Настройки и очередь остаются отдельно.
Работающая передача перезапускается и проверяется; остановленная остаётся остановленной.
Настройка запуска после перезагрузки не меняется. Если новая служба сразу не запускается
или команда перезапуска завершается ошибкой, возвращается и запускается прежняя программа.
Ручной возврат прежней программы также сохраняет остановленное состояние передачи.
Доступность площадок проверьте живым сообщением; включённая служба сама по себе не доказывает доставку.
Обновление проекта сохраняет общий защищённый приёмник и VPN. Обновление общей программы Caddy
выполняется отдельно её штатным способом с учётом всех обслуживаемых доменов.

Для закрытой резервной копии выбранного проекта остановите только его передачу и VPN,
сохраните прежнее состояние запуска. В личном терминале зашифруйте данные, например

```sh
sudo telemax --project mybridge stop
sudo systemctl stop telemax-vpn-mybridge
sudo apt-get install -y gnupg
sudo tar -C / -czf - var/lib/telemax-projects/mybridge etc/telemax/projects/mybridge opt/telemax/projects/mybridge/project.json | gpg --symmetric --cipher-algo AES256 --output "$HOME/mybridge-backup.tar.gz.gpg"
```

Пароль вводите в личном окне. Сохраните зашифрованный архив на своём устройстве, пароль отдельно.
На прежнем сервере возобновите только службы, которые работали перед копированием.
Для восстановления установите тот же именованный проект, оставьте его остановленным,
проверьте список архива через `gpg --decrypt ... | sudo tar -tzf -` и восстановите только
его собственные пути. Исправьте владельца данных на `telemax-mybridge`, папки закройте
правами 700, файлы 600. Привязку, настройку и вход повторять при целых данных не требуется.
Общий приёмник, его сертификаты и настройки других доменов поверх работающего сервера не восстанавливайте.
На другом сервере заново подключите домен командой `https` и получите сертификат его штатным способом.
Перед запуском VPN проверьте свободные подсеть, интерфейс и UDP-порт из закрытой копии.
Для VPN с записью `creation.json` повторите `create` с прежними проверенными параметрами,
он восстановит собственную службу без изменения ключей и сохранит остановленное состояние.
После проверки запустите её командой `sudo systemctl start telemax-vpn-mybridge`. При смене публичного IP нужен
отдельный перенос адреса и клиентских настроек, автоматической замены адреса команда не делает.
При переносе также проверьте свободный местный порт из `project.json` и `config.json`.
Затем запустите выбранный проект и пройдите живую проверку. Старую копию держите остановленной.

Старая установка без имени продолжает хранить данные в `/var/lib/telemax`, программу в
`/opt/telemax/current`, VPN-профиль в `/etc/telemax-vpn`. Её команды остаются без `--project`.
Для обновления такой установки выполните новый `install.sh --update` без имени.
Новая установка с именем использует `/opt/telemax/projects/mybridge`,
`/var/lib/telemax-projects/mybridge`, `/etc/telemax/projects/mybridge/vpn`,
службы `telemax-mybridge` и `telemax-vpn-mybridge`. Журнал пересылки ограничен своей службой.
Остановить или вернуть VPN выбранного проекта можно через `sudo systemctl stop telemax-vpn-mybridge`
и `sudo systemctl start telemax-vpn-mybridge`. Остановка сохраняет ключи и устройства.
Общие правила не очищаются, передача пакетов для других проектов остаётся включённой.

Неизвестные исходы отправок остаются остановленными и после восстановления.
Если резервной копии нет, сохранённые соответствия копий восстановить из одного MAX невозможно:
нужна новая настройка и новые сообщения. Новая установка не обещает восстановление старой переписки.
